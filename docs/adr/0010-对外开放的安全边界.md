# ADR-0010：对外开放的安全边界

- 状态：**已决定**
- 触发：需求「服务启用后，别人能通过一个**长期有效**的 URL 访问」。
- 相关：ADR-0001（本机工具路线）、ADR-0009（成本库是本项目唯一可写的库）、
  `ops/public/README.md`（可复制命令）、`docs/路线图-基于原产品功能对照.md` 阶段 D

## 一、结论

对外开放**不是设置一个环境变量**，而是三条同时成立的边界：

| # | 边界 | 落点 |
|---|---|---|
| 1 | **配置合规才允许启动**（fail-closed） | `api/preflight.py`，`OZON_PUBLIC_MODE=1` 时生效 |
| 2 | **同源单端口发布**（页面与接口同一进程） | `api/app.py` 挂载 `web/dist` |
| 3 | **访问控制由身份网关负责**，不靠口令强度 | Tailscale tailnet 或 Cloudflare Access |

第 3 条是这份 ADR 里最重要的一句：本系统**没有登录失败锁定与限速**，
所以「只允许我邀请的人」必须由网关保证。靠「口令够长所以安全」是自我安慰。

## 二、为什么必须 fail-closed，而不是打印警告

默认配置是给「只在本机自己用」的，它**故意**好记：

| 默认 | 本机 | 挂到公网 |
|---|---|---|
| 三个账号口令 = 用户名（`admin`/`admin`） | 方便 | **等于没有认证** |
| `OZON_JWT_SECRET` 有仓库里的默认值 | 无所谓 | 默认值公开在版本历史里，**任何人都能自己签一个合法令牌** |
| 用户表就是仓库里的 `api/data/users.json` | 跟随仓库 | 口令哈希随公开仓库一起走 |

这三条一起意味着：默认配置下的对外服务**可以被任何人完全接管**。
所以 `api/preflight.py` 的选择是**拒绝启动**并逐条说明怎么修 ——
警告会被忽略（尤其在被自动化脚本启动时），拒绝启动不会。

检查项与理由（实现里逐条注释）：

1. JWT 密钥非默认值且 ≥ 32 位；
2. 用户表**不在仓库目录内**（`_inside(path, repo_root())`）；
3. 每个账号都**过不了**「用户名 + 常见弱口令」这组候选
   —— 靠哈希逐个试，能抓到「改成 123456」这种偷懒；
4. 存在前端**生产构建**产物；
5. 数据源文件存在（对外服务却在首页 503 很难看，也让排查变慢）。

密钥与口令**从不打印**：只报「哪一项不合格 + 怎么修」。

## 三、为什么同源单端口，而不是「前端 8848 + 后端 8849 都挂出去」

Vite **开发服务器**不能对外：

* 它按需编译并**直接提供源码**（含 `.env`、注释、接口路径）；
* 它有 `server.fs.allow` 与 `/@fs/` 这类**读本机文件**的入口，
  历史上出过多次任意文件读取问题；
* 它不是为并发与稳定性设计的。

所以对外只提供**构建产物**，并且由 FastAPI 同源提供：

```
隧道/反代 → 127.0.0.1:8849 ─┬─ /       → web/dist（静态）
                            └─ /api/*  → FastAPI 路由
```

好处：**一条隧道规则**、**不需要 CORS**（我们刻意不加 `allow_origins=['*']`）、
**不需要额外进程**。代价：改前端后要重新 `pnpm build:pro`。

> 顺序陷阱（踩过，已写进代码注释）：Starlette 按**注册顺序**匹配路由，
> `/` 挂载必须放在**文件末尾**。第一版放在 `include_router` 之后、
> `/api/health` 之前，结果 `/` 与 `/api/costs` 都正常、**唯独 `/api/health` 404**。

## 四、两条路线，以及为什么「长期有效」是个硬条件

| | Tailscale | Cloudflare Tunnel（命名隧道） |
|---|---|---|
| 长期 URL | ✅ `https://<机器>.<tailnet>.ts.net` | ✅ `https://ozon.你的域名` |
| 需要域名 | **不需要** | 需要（且 NS 托管到 Cloudflare） |
| 访问控制 | tailnet 成员（每人装客户端、接受邀请） | **Cloudflare Access**：邮箱验证码，同事**零安装** |
| HTTPS | 自动签发 | 自动 |
| 免费额度 | 个人版免费 | 隧道免费；Access 免费版 50 用户 |

**必须区分命名隧道与临时隧道**：`*.trycloudflare.com` 与 ngrok 的随机域名
**每次重启都会变**，不满足「长期有效」。ngrok 免费账号可固定 1 个静态域名，
但免费版没有 Access 那类身份网关。

**与阶段 D（迁移到云服务器）的关系**：
* 走 Tailscale —— 新机器加入同一 tailnet，**URL 不变**（不用通知所有人换地址）；
* 走 Cloudflare —— 隧道换个 `credentials-file` 指向新机器即可，URL 也不变。
两条都能满足「先本机、后上云」，所以**现在选哪条都不堵死后路**。

## 五、明确不做的事

* **不做端口转发 / 不开公网 IP**：隧道是从本机连出去的，不需要在路由器/防火墙上开口子。
  端口转发会把服务直接暴露且没有 TLS。
* **不加 CORS `allow_origins=['*']`**：接口同源，加了只会把接口暴露给任意网页。
* **不做免密/共享账号**：三个角色对应不同可见范围（root / finance / store_operator），
  共享账号等于放弃这套隔离。
* **不开 `tailscale funnel`**：那是把服务放回公网，与「只允许我邀请的人」相反。
* **不把口令或密钥写进仓库**：它们只存在于
  `<DATA_ROOT>Platform\config\`（仓库之外，也不进公开仓库）。

## 六、已知缺口（如实记录）

| 缺口 | 影响 | 计划 |
|---|---|---|
| **没有登录失败锁定与限速** | 能到达登录页就能无限试口令 | 由网关兜底（第三节的路线选择）；应用层限速列入阶段 E |
| **没有访问审计** | 谁在什么时候看过哪些数据查不到（只有成本变更留痕） | 阶段 E 的「审计中心」（PRD T-15） |
| 会话是 JWT，没有刷新/吊销列表 | 令牌泄露后在过期前一直有效 | 阶段 E 与账号服务端化（T-06）一起做 |

这三条都不影响「能不能对外」，但**影响「对外之后有多可控」**，
所以写在 README 显眼处，也写在这里 —— 不要让下一个人以为它们已经解决了。
