# 如何启动与测试

本文档说明**你自己怎么把前端跑起来看、怎么验证改动没坏**。

## 一、最快看到页面（30 秒）

```powershell
cd D:\xzy\ozon-finance\web
pnpm dev
```

控制台会打印 `➜ Local: http://localhost:8848/`，浏览器打开它。

**登录**：用户名 `admin`、密码 `123456`（离线 mock，任意非空账号都能进）。
进去就是「单店财务看板」。

停止：在控制台按 `Ctrl+C`。

> 端口 8848 定义在 `web/.env` 的 `VITE_PORT`。若被占用，改这个值即可。

## 二、这一页现在长什么样

渲染截图见 `web/docs/单店看板-实际渲染截图.png`。页面上有：

| 区块 | 内容 |
|---|---|
| 四大指标卡 | 实际利润合计、预估利润合计、核算完成率、待发货逾期单数 |
| 趋势图 | 近 14 天「实际利润 vs 预估利润」双折线 |

⚠️ **当前所有数据都是页面里写死的 mock**，不是真实数据，也还没接后端。
三个业务口径要留意的点（接后端时必须替换）：

1. **利润构成图把 ₽ 的直接净额按 mock 汇率折成了 ¥** 才能与采购成本等项目同图比较。
   真实接口最好直接下发统一币种，避免前端做汇率换算。
2. **预估利润合计**与**待发货逾期单数**的 mock 数值是凑数演示用的。
3. 明细表的「核算状态」列依赖 `unknown_reason`，真实数据里它是枚举，
   当前 mock 只覆盖了「完整」和两种不完整原因。

## 三、前端改动后的自检

```powershell
cd D:\xzy\ozon-finance\web
pnpm build:pro     # 生产构建，含 vue-tsc 类型检查
```

**这是前端的硬性验收**：退出码必须是 0。
它比 `pnpm dev` 严格 —— dev 只转译不检查类型，类型错误要到构建才暴露。

其他可用命令：

```powershell
pnpm type:check    # 只做类型检查，最快
pnpm lint:eslint   # 代码规范
pnpm build:dev     # 出开发模式产物
```

## 四、后端 / 财务口径的测试

前端页面不涉及财务计算。真正的口径验证在 `core/`：

```powershell
cd D:\xzy\ozon-finance
python -m unittest core.tests.test_profit_golden
```

它会做两件事：

- **夹具回归**：用冻结的 147 单黄金样本重算，与既有系统的结果逐个比对
- **生产库全量对账**：直接读 `<DATA_ROOT>`（只读），
  核对 10,899 单的金额、直接净额、完成标记

期望结果：`Ran 14 tests, OK`。当前基线是**实际利润 6668 单核对，0 处不符**。

只跑夹具（不需要生产库）：

```powershell
python -m unittest core.tests.test_profit_golden.GoldenFixtureTest
```

## 五、改动怎么走流程（强制）

这个项目的 git 钩子会**拦住不合规的操作**，不是靠自觉：

```powershell
cd D:\xzy\ozon-finance

git switch dev                     # 1. 开发在 dev
# …… 改代码 ……
git add -A && git commit           #    提交时自动跑夹具回归，红了提交不进去

git switch main
git merge --no-ff dev -m "merge: …"  # 2. 合并进 main，自动跑完整回归（含生产库对账）
git push origin main && git push origin dev   # 3. 推送，pre-push 再跑一次完整回归
git switch dev
```

三个门禁的行为：

| 钩子 | 触发 | 跑什么 |
|---|---|---|
| `pre-commit` | dev 上提交 | 夹具回归（约 2 秒）；**在 main 上直接提交会被拒绝** |
| `pre-merge-commit` | 合并进 main | 完整回归（含生产库，约 13 秒） |
| `pre-push` | 推送 | 完整回归（不可撤回的动作，不提供快速档） |

确实需要绕过：`git commit --no-verify`。
**但合并与推送不要绕过** —— 那等于把没验证的代码放进主干或推上远端。
